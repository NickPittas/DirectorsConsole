Scope: only the permitted source regions; prior successful runs are user-supplied evidence, not rerun here. All paths below are relative to `CinemaPromptEngineering/` unless stated otherwise.

## Ranked findings
1. **High — cross-app prepare cannot express the requested I2V contract.** `dispatchPromptEngineerAgentAction(request, isCurrent)` accepts `{operation:'prepare', userPrompt, targetModel?}` only (`frontend/src/services/agent-prompt-engineer-actions.ts:11–14,44–75`). It copies config/preset, but copies skill version/task/adapter only when target strings match; it passes no images, image mode, enhancement context, or shared media identity. A target override alone cannot select exact LTX 2.5 I2V.
   `api/main.py:2546–2663` defaults omitted-media requests with a known video profile to effective `task='t2v'`. That legacy default does NOT itself set `inferred_skill_task`; therefore exact T2V skill guidance is not guaranteed either. Same-target inherited explicit I2V can fail media validation; inherited unsupported selections can fail availability checks. This is a real missing request contract, not proof that every call fails identically.
2. **Medium — existing deterministic generation is task-independent, but not a demonstrated substitute for the complete selected style.** `generate_prompt(request: GeneratePromptRequest)` (`api/main.py:136–148,280–302`) accepts `{project_type,config,target_model='generic'}` and returns `{prompt,negative_prompt,validation}`. It instantiates `PromptGenerator` and validates config without PE task/media gates, but does not call `_enhancement_preset_context(request: EnhancementInput) -> tuple[dict|None,dict|None]` (`:2397–2422`). Enhancement explicitly supplies that helper's authoritative preset and cinematography-style dictionaries to `build_enhancement_prompt` (`:2667–2685`). Do not assume the deterministic string alone preserves that extra guidance; generator internals were outside scope.

Proposed dispatcher call: `dispatchPromptEngineerAgentAction({operation:'constraints'})` — no user prompt, target, task, or media arguments.

No PE target switching or PE media access is needed.

Preserve existing requests/responses with optional new response fields. ## Freshness, identity, and unchanged validation
Before accepting the four outputs, compare the current `snapshot.revision` with the captured constraint revision; a changed revision invalidates the batch rather than silently mixing styles. Existing `getRevision()` includes target/task/media as well as style (`frontend/src/CinemaPromptEngineering.tsx:2326–2352`), so reuse is conservative: unrelated PE changes can invalidate results, but no PE selection is required to read constraints. Do not add a new revision scheme in this correction.
Keep captured shared-media identity bound to each result and revalidate it at the existing downstream import/bind/submit boundary. The allowed PE files contain no shared-media registry lookup: PE revision checks cannot establish asset identity or stop a shared asset being replaced. Parent must locate and retain the existing chain's identity checks before wiring this result; echoing an ID is not validation. No synthetic bytes, invented confirmed roles, or claims of generation readiness.
Existing constrained validation remains `validate_apply({preparationId,prompt,apply})`: stored input + prepared target/task/dialect/context/fingerprint, revision checks before/after validation and apply, and one-use preparation (`frontend/src/services/agent-prompt-engineer-actions.ts:79–110`). Backend reconstructs preparation and rejects context/fingerprint drift with 409 (`api/main.py:2742–2764`). Keep this path for users explicitly requesting PE validation/apply; the new read does not authorize apply.
For comparison, option (b) would need explicit `skillModelVersion`, `skillTask`, `conditioningAdapter`, `enhancementContext`, and genuine resolved `images`/`imageMode`, plus identity revalidation. Existing `PromptEnhancementInput`/`EnhancementContext` (`frontend/src/api/client.ts:65–79,104–119`) can carry those values, but the dispatcher currently cannot. `resolve_prompt_skill(*,target_model,model_version,task,inferred_task,conditioning_adapter,dialect_id,image_mode,images,asset_roles)` calls `_validate_media` (`api/providers/prompt_skill_resources.py:220–263,454–462`), enforcing roles/counts/modes. This is a larger integration than the guidance-only need; do not weaken its preflight.
Console's ordinary prompt generation continues with its explicit model/task guidance alone. Request the new PE constraint read only when the user asks to use PE's selected style. Neither path changes the model/provider or falls back automatically.
