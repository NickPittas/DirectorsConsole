# Codex app-server contract (official docs checked 2026-11-06)

Sources: [App Server](https://learn.chatgpt.com/docs/app-server), [Config Reference](https://learn.chatgpt.com/docs/config-file/config-reference), [Environment Variables](https://learn.chatgpt.com/docs/config-file/environment-variables).

## Documented RPC contract
- Initialize once per transport: `initialize` request with `params.clientInfo` and `params.capabilities.experimentalApi: true`; then send `initialized` notification. Experimental fields/methods require that opt-in.
- Auth state without credential material: `account/read` request `{refreshToken:false}`; response `{account:null|{type,...},requiresOpenaiAuth}`. Examples expose account type/email/plan, not tokens. Do not request refresh for a state-only check.
- Read-only effective settings: `config/read` request `{method:"config/read",id:n,params:{includeLayers:false}}`; response contains `result.config`. This is read-only; `config/value/write` and `config/batchWrite` mutate user config and are out of scope.
- `model/list` request example: `{limit:20,includeHidden:false}`; result `{data:[{id,model,displayName,defaultReasoningEffort,supportedReasoningEfforts,inputModalities,isDefault,...}],nextCursor}`. Docs show a response cursor but do not specify a request cursor field. Provider identity is `thread.modelProvider` (e.g. `openai`), not a documented `model/list` field.
- `thread/start` example accepts `model`, `cwd`, `approvalPolicy`, `sandbox`, `serviceName`; response includes `thread.id`, `sessionId`, `ephemeral`, `modelProvider`. `dynamicTools` and `historyMode` are experimental. Persistent local threads default to paginated history.
- Resume with `{threadId,excludeTurns:true}`; page history through `thread/turns/list` and `thread/items/list`. `thread/start` docs expose no custom history-directory field.
- Turn input explicitly documents `{type:"text",text}`; `{type:"image",url:"https://…"}`; `{type:"localImage",path:"/…"}`. Data URLs are not documented as supported input.
- `turn/start` returns an in-progress turn; consume notifications. `turn/interrupt` takes `{threadId,turnId}` and returns `{}`; completion then reports `status:"interrupted"`.
- Stream `item/started` / `item/completed` (final item authoritative), `item/agentMessage/delta`, reasoning summary deltas, and `turn/completed`. Raw reasoning deltas are model-dependent. `turn/completed` is the settlement signal; inspect final status/error.
- Dynamic tools: experimental `thread/start.dynamicTools`; invocation sequence is `dynamicToolCall` item start → server `item/tool/call` request → client reply with content items → completed item with status/contentItems or success. The page does not give registration or JSON-RPC request/reply field schemas; parent pins the binary schema separately.

## Isolation and persistence findings
- Individually documented gates include `features.shell_tool=false`, `features.view_image=false`, `web_search="disabled"`, per-server `mcp_servers.<id>.enabled=false`, and `apps._default.enabled=false`. `plugins._default.enabled=false` has override caveats; these are not a complete tool deny-list.
- `sandboxPolicy`/approval settings govern command execution. The app-server also documents `fs/*` RPCs; docs do not establish that read-only sandboxing removes those RPCs or that the client cannot invoke them.
- `CODEX_HOME` selects the app-server's root for config, auth, logs, sessions, skills, and package metadata; the directory must already exist. `history.persistence="none"` only documents disabling `history.jsonl` transcript saves; it does not establish that persistent thread rollouts stop.
- **Blocker:** official docs do not prove a supported configuration that disables every built-in shell/file/web/MCP/app/plugin/extension tool while allowing only supplied dynamic tools. Do not claim isolation or guess a key; require a pinned-binary schema/behavior check and enforce the allow-list at the trusted host boundary.
- Config docs do not promise read-only global config enforcement. Keep the app-owned `CODEX_HOME` config isolated; read-only protection is not part of this RPC contract.
